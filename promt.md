# Задача: разработать полноценного Telegram-бота для продажи 30-дневного курса английского

Ты — senior backend-разработчик, специализирующийся на Telegram-ботах, Node.js, grammY, SQLite и интеграциях с платёжными системами.

Разработай готовый к запуску Telegram-бот для автоматизированной продажи цифрового образовательного продукта.

Не ограничивайся архитектурой, псевдокодом и примерами. Создай полноценный проект с файлами, рабочей бизнес-логикой, миграциями базы данных, обработкой ошибок, инструкцией по запуску и тестами.

Если у тебя есть доступ к файловой системе и терминалу, самостоятельно создай проект, установи зависимости, запусти тесты, исправь найденные ошибки и проверь основные пользовательские сценарии.

## 1. Технологический стек

Используй:

- Node.js LTS.
- TypeScript.
- grammY для Telegram Bot API.
- SQLite через better-sqlite3.
- YooKassa API для приёма платежей.
- Express для HTTP-сервера и обработки webhook от YooKassa.
- Zod для валидации конфигурации и входящих данных.
- dotenv для переменных окружения.
- Pino для структурированных логов.
- Vitest для тестирования.
- Поддерживаемые актуальные версии зависимостей.

Используй ESM и строгий TypeScript.

Не добавляй Docker, Redis, PostgreSQL, React или отдельную административную панель без необходимости. На первом этапе проект должен быть простым и недорогим в обслуживании.

SQLite подходит для небольшого проекта при условии правильной настройки транзакций, индексов и резервного копирования. Учти, что несколько реплик приложения с общей SQLite-базой не должны запускаться без специально предусмотренной архитектуры хранения.

## 2. Цель продукта

Бот продаёт курс английского языка для русскоязычных начинающих.

Основная воронка:

1. Пользователь переходит из Telegram-канала или Reels в бота.
2. Нажимает /start.
3. Получает приветствие и бесплатный PDF-чек-лист.
4. Знакомится с платным курсом.
5. Покупает курс за 500 RUB через YooKassa.
6. После подтверждения успешной оплаты получает доступ к курсу.
7. В течение 30 дней получает ежедневные уроки и задания.
8. Отправляет ответы боту.
9. Получает обратную связь и отслеживает свой прогресс.
10. Завершает курс и получает итоговый результат.

Язык интерфейса — русский. Английские слова и предложения сопровождаются русским переводом, если это необходимо для обучения.

Весь пользовательский интерфейс должен быть понятным человеку без технических знаний.

## 5. Регистрация и бесплатный лид-магнит

При первом запуске:

1. Сохрани Telegram user ID.
2. Сохрани username, если он доступен, и дату регистрации.
3. Сохрани источник перехода, если он передан через параметр `/start`.
4. Отправь приветственное сообщение.
5. Предложи получить бесплатный чек-лист.
6. Отправь PDF из `FREE_CHECKLIST_PATH`.

Поддерживай deep links вида:

`https://t.me/<BOT_USERNAME>?start=reels_english_01`

Обрабатывай start-параметры безопасно и сохраняй атрибуцию источника.

Если PDF отсутствует, сообщи об этом администратору и предложи пользователю получить материал позднее. Не допускай падения бота.

При повторном `/start` не дублируй регистрацию и не сбрасывай прогресс курса.

Не отправляй рекламные сообщения пользователям, которые не дали соответствующего согласия.

## 6. Продажа курса

Название продукта: «Английский за 30 дней».

Цена: 500 рублей за один доступ к курсу.

В описании курса объясни, что пользователь получает:

- 30 ежедневных уроков.
- Объяснения на русском языке.
- Примеры с переводом.
- Практические задания.
- Проверку ответов.
- Повторение изученного.
- Отслеживание прогресса.
- Итоговый тест.

Не обещай свободное владение английским за 30 дней. Формулируй результат как освоение конкретных базовых конструкций и практику простых диалогов.

После нажатия «Купить курс»:

1. Покажи программу, цену и условия предоставления доступа.
2. Предложи перейти к оплате.
3. Создай платёж через YooKassa.
4. Сохрани платёж и внутренний заказ в SQLite.
5. Отправь пользователю ссылку на оплату.
6. Объясни, что доступ будет открыт после подтверждения платежа.
7. При успешной оплате отправь подтверждение и кнопку начала курса.

Не выдавай доступ только на основании перехода пользователя по ссылке возврата или нажатия кнопки «Я оплатил».

## 7. Интеграция YooKassa

Используй официальный API YooKassa и актуальную документацию:

https://yookassa.ru/developers/

Создавай платежи через `POST /v3/payments`.

Для каждого запроса на создание платежа используй уникальный `Idempotence-Key`.

Передавай:

- Сумму `500.00`.
- Валюту `RUB`.
- Подтверждение типа `redirect`.
- URL возврата из `YOOKASSA_RETURN_URL`.
- Описание покупки.
- Metadata с внутренним ID заказа и Telegram user ID, если формат допустим.

Сохраняй в SQLite идентификатор платежа YooKassa, ID заказа, пользователя, сумму, валюту, статус, дату создания и дату изменения.

Реализуй webhook для событий `payment.succeeded` и `payment.canceled`.

Требования к обработке webhook:

- Принимай только ожидаемые события.
- Не доверяй полям входящего запроса без проверки.
- Получай актуальный статус платежа через API YooKassa перед выдачей доступа.
- Сверяй сумму, валюту, идентификатор платежа и связанный заказ.
- Учитывай возможность повторной доставки одного webhook.
- Выдавай курс ровно один раз для одной покупки.
- Не выдавай курс по отменённому или неподтверждённому платежу.
- Не полагайся только на секретный URL webhook как на подтверждение подлинности платежа.
- Возвращай HTTP 200 после корректной обработки уведомления, если дальнейшая обработка надёжно завершена либо сохранена для повторной обработки.
- Если обработка не завершилась, используй безопасный механизм повторной обработки и соответствующий HTTP-ответ.
- Не создавай бесконечные повторные платежи при повторном нажатии кнопки.

Реализуй создание платежа, получение статуса платежа, повторную проверку статуса и обработку ошибок API.

Сделай идемпотентную выдачу доступа с помощью транзакции SQLite и ограничений уникальности.

Учти, что сетевой запрос нельзя считать атомарной частью транзакции SQLite: продумай обработку ситуации, когда платёж создан у провайдера, но приложение завершилось до сохранения результата.

При необходимости используй transactional outbox или эквивалентный механизм надёжной доставки сообщений.

Не реализуй автоматические списания и подписки. Это разовая покупка.

Если для обязательных фискальных чеков необходима дополнительная настройка YooKassa, опиши её отдельно. Не утверждай, что интеграция автоматически обеспечивает соблюдение всех требований российского законодательства.

## 8. Модель доступа к курсу

После успешной оплаты создай запись о доступе пользователя к курсу.

Храни:

- Telegram user ID.
- ID продукта.
- ID заказа.
- Дату покупки.
- Дату начала обучения.
- Номер текущего дня.
- Статус курса.
- Дату завершения.
- Настройки времени отправки уроков.

Пользователь должен иметь доступ к уже открытым урокам после перезапуска бота.

Не создавай второй курс при повторном webhook или повторном нажатии «Начать обучение».

Предусмотри возможность ручного предоставления и отзыва доступа администратором с обязательным логированием действий.

## 9. Выдача уроков по расписанию

Курс состоит из 30 последовательных дней.

Реализуй планировщик задач на базе устойчивого механизма хранения расписания в SQLite. Можно использовать подходящий scheduler, но состояние отправки уроков должно сохраняться в базе.

Требования:

- По умолчанию отправлять урок в 10:00 по `Europe/Moscow`.
- Часовой пояс настраивается через окружение.
- Не отправлять дважды один и тот же урок одному пользователю.
- После перезапуска приложения продолжать выдачу.
- Если бот был выключен, не отправлять сразу все пропущенные уроки подряд.
- Для пропущенных отправок реализуй понятную стратегию восстановления: отправляй только актуальный урок и позволяй открыть предыдущие через меню.
- Сохраняй запланированное время, статус отправки, количество попыток и последнюю ошибку.
- Учитывай Telegram rate limits и ошибки временной недоступности.
- Не отправляй уроки пользователям, которые заблокировали бота.
- Предусмотри возможность временно приостановить обучение и продолжить его позднее.

Продумай, что означает «30 дней»: календарные дни по часовому поясу курса. День 1 начинается после активации доступа, следующие дни наступают согласно расписанию.

Не запускай конкурентные экземпляры планировщика без механизма блокировки задач.

## 10. Учебная программа

Создай отдельный файл `src/content/course.ts` с содержанием всех 30 уроков.

Каждый урок должен содержать:

- `day` — номер дня.
- `title` — название.
- `objective` — цель.
- `explanation` — простое объяснение на русском.
- `examples` — английские примеры и переводы.
- `exercise` — задание.
- `answerKey` — правильные ответы для объективно проверяемых упражнений.
- `hint` — подсказка.
- `review` — материал для повторения.
- `estimatedMinutes` — примерное время занятия.

Пример программы:

Дни 1–7:
- Знакомство, приветствия, местоимения.
- Глагол to be.
- Утверждения и отрицания.
- Общие вопросы.
- Вопросительные слова.
- Числа, возраст, базовая информация.
- Повторение и мини-тест.

Дни 8–14:
- Present Simple.
- Повседневные действия.
- Do и does.
- Отрицания.
- Частотные наречия.
- Время и распорядок дня.
- Практический тест.

Дни 15–21:
- Предпочтения и интересы.
- Can и простые просьбы.
- Еда и заказ в кафе.
- Покупки и цены.
- Направления и места.
- Семья и описание людей.
- Диалоги из повседневной жизни.

Дни 22–30:
- Повторение основных конструкций.
- Простые планы на будущее.
- Прошедшее время: базовые формы.
- Составление вопросов.
- Диалоги и ответы о себе.
- Работа над типичными ошибками.
- Повторение ключевой лексики.
- Итоговая практика.
- Финальный тест и результаты.

Это предварительный план. Создай последовательные, педагогически корректные материалы с возрастающей сложностью.

Не допускай выдуманных правил, неправильных переводов и противоречий между уроками.

## 11. Приём и проверка заданий

После урока пользователь может отправить ответ текстом.

Поддерживай типы упражнений:

1. Выбор правильного ответа с inline-кнопками.
2. Вставка пропущенного слова.
3. Перевод короткого предложения.
4. Составление предложения.
5. Свободный текстовый ответ.
6. Повторение ранее изученных конструкций.

Для заданий с однозначным ответом реализуй автоматическую проверку.

При сравнении ответов допускай безвредные различия в регистре и лишних пробелах. Пунктуацию нормализуй только там, где это не меняет смысл задания.

Для заданий со свободным ответом не объявляй ответ неправильным только потому, что он не совпадает посимвольно с образцом.

Предусмотри два режима проверки:

- Без внешнего ИИ: проверка по заранее подготовленным правилам и образцам, а для неоднозначных ответов — показ правильного варианта и возможность запросить помощь.
- Опциональная проверка через внешний LLM API, отключённая по умолчанию.

Если LLM интегрирован, API-ключ должен храниться в окружении. Используй ограниченный контекст, таймауты и обработку ошибок. Не передавай личные данные пользователя без необходимости. Результат LLM не должен автоматически менять статус оплаты или доступ к курсу.

После каждого ответа сообщай:

- Правильно ли выполнено задание.
- Правильный ответ или один из допустимых вариантов.
- Короткое объяснение ошибки.
- Следующий шаг.

Храни историю ответов, результаты, количество попыток и дату выполнения.

## 12. Прогресс пользователя

Реализуй `/progress` и соответствующий пункт меню.

Показывай:

- Текущий день курса.
- Количество завершённых уроков.
- Количество оставшихся уроков.
- Процент завершения.
- Результаты заданий.
- Следующий урок.
- Возможность открыть доступные предыдущие уроки.

Не считай урок завершённым только из-за того, что он был отправлен. Определи явный критерий завершения, например выполнение обязательного задания.

После 30-го дня покажи поздравление, сводку прогресса и результаты итогового теста.

## 13. Напоминания

Добавь настраиваемые напоминания о невыполненном уроке.

По умолчанию можно отправлять не более одного напоминания в день, если пользователь не завершил обязательное задание.

Учитывай настройки пользователя, часовой пояс и статус курса.

Предусмотри команды или кнопки для отключения напоминаний.

Не рассылай маркетинговые сообщения без согласия пользователя.

## 14. Администрирование

Реализуй защищённые команды для Telegram ID, перечисленных в `ADMIN_TELEGRAM_IDS`.

Администратор может:

- Просматривать количество пользователей.
- Просматривать количество бесплатных регистраций.
- Просматривать число оплаченных заказов.
- Просматривать суммарную выручку по успешным платежам.
- Просматривать число активных курсов.
- Просматривать количество завершённых курсов.
- Находить пользователя по Telegram ID.
- Выдавать и отзывать доступ.
- Повторно отправлять урок.
- Отправлять сервисное сообщение пользователю.
- Просматривать последние ошибки и статусы задач.
- Повторно запускать безопасную обработку зависшей задачи.

Ограничь частоту административных операций и записывай аудит изменений.

Не показывай секретные ключи и полные платёжные реквизиты в административном интерфейсе.

Все административные команды должны проверять права доступа на сервере, а не только скрываться из меню.

- `course_access`
- `lessons`
- `lesson_deliveries`

- `reminders`
- `webhook_events`
- `outbox`
- `admin_audit_log`

Можно объединять или разделять таблицы, если это улучшает модель данных.

Требования:

- Внешние ключи включены.
- Уникальные ограничения для Telegram user ID и идентификатора платежа.
- Индексы для выборок запланированных уроков, заказов и активных курсов.
- Миграции версионируются.
- Денежные значения хранятся безопасно, например в копейках как целые числа.
- Все операции изменения состояния выполняются транзакционно там, где это необходимо.
- Время хранится в UTC, а расписание рассчитывается с учётом настроенного часового пояса.
- Реализовано резервное копирование SQLite без копирования потенциально неконсистентного файла во время записи.

## 18. UX и обработка ошибок

Используй дружелюбный тон.

Примеры сообщений:

При успешной оплате:

«Оплата прошла успешно! 🎉

Добро пожаловать на курс “Английский за 30 дней”.

Тебя ждут короткие уроки, практика и постепенное закрепление материала.

Нажми кнопку ниже, чтобы начать обучение».

При повторном webhook не отправляй дублирующие поздравления.

Если платёж ожидает подтверждения, объясни, что доступ откроется автоматически после подтверждения.

Если проверка задания не удалась из-за технической ошибки, сохрани ответ и предложи повторить проверку без потери данных.

Если пользователь отправляет сообщение вне ожидаемого сценария, подскажи доступные действия, не сбрасывая прогресс.
